Detailed Description

E3SM-SPEC: the Spectrum service model

E3SM-SPEC is the E3 service model for spectrum sensing and spectrum sharing. A RAN that offers it publishes a map of free time and frequency resources to dApps. It also accepts two controls that change how the scheduler uses the spectrum. A dApp can report the PRBs it found occupied, and an xApp can suggest PRBs to block.

This directory is the specification of the service model: what the fields mean, how each message is encoded, and how the procedures run. The E3 Application Protocol that carries these messages is specified in the E3AP specification.

Item Value
E3 RAN function ID 1
Service model name spectrum_sm
Service model version 1
Telemetry identifiers 1 to 5 (sensing ranges, timestamp, SFN, slot, beam)
Control identifiers 1 (PRB block), 2 (sensing policy)
Encodings APER, JSON, Protocol Buffers. The RAN serves one per run.
Message types RAN function data, sensing indication, dApp control, dApp report, xApp control, apply outcome

Scope

The present document specifies the E3 Service Model (E3SM) "Spectrum" for the RAN function that exposes spectrum sensing telemetry and spectrum control.

The document defines the identity of the RAN function and how a RAN announces it. It defines the information elements of every message, and the procedures that use them. It defines the encodings, the units, the clocks and the limits of each field. It also defines how a receiver handles a message that is unknown or wrong.

The document does not define the E3 Application Protocol. It does not define the E2 service model that carries dApp traffic to an xApp. It does not define how a scheduler enforces a PRB block internally.

Terms, symbols and abbreviations

Terms

For the purposes of the present document, the terms and definitions of the E3AP specification [1] and the following apply.

Sensing range: a rectangle in the time and frequency grid of one slot. It has a first symbol, a number of symbols, a first PRB and a number of PRBs. No scheduled transmission uses the resources inside it.

Sensing ring: a ring of fixed size slots in POSIX shared memory. The RAN writes one ring slot for each sensing publish. It holds the sensing ranges of that publish.

Sensing publish: the moment the scheduler hands the sensing ranges of one slot to the service model.

PRB block: a set of PRBs that the scheduler treats as occupied, in uplink and in downlink, until the set is replaced or cleared.

Sensing policy: a list of symbol masks, one for each slot of a frame. The uplink scheduler prefers time domain allocations that leave the masked symbols free.

Apply outcome: the report of the RAN on what applying a PRB block control did, and when.

General

Notations

For the purposes of the present document, the following notations apply.

Message: a message is written in capital letters, for example E3 RAN FUNCTION DATA.

Information element: an information element (IE) is written in italic font with its name as in the grammar, for example samplingThreshold.

Value: the value of an IE is written in quotation marks, for example "0".

Clause numbers: a reference to a clause of another specification names that specification, for example "E3AP [1]".

Forwards and backwards compatibility

The grammar of the service model is version 1. Every payload alternative and every structure that can grow carries an extension marker. A receiver that meets an alternative it does not know shall reject the message as described in clause 9. A receiver shall ignore an extension field that it does not know, where the encoding allows it.

An extension alternative in an APER choice changes the width of the choice index. A sender and a receiver therefore need the same version of the grammar for the messages that already exist. Clause 8 gives the rule and the effect.
