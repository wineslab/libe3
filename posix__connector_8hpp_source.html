23/**
24 * @brief POSIX socket-based E3 connector: one endpoint per dApp
25 *
26 * Supports TCP, SCTP and IPC. A dApp opens one connection to the RAN's single
27 * endpoint and the setup, inbound and outbound traffic all use it; the three
28 * channels of E3Connector are logical. The first PDU on a connection is the
29 * dApp's setup request and goes to recv_setup_request(); every later PDU goes
30 * to receive(). The inbound thread is the only reader of the sockets, so the
31 * receive path costs the same as with one channel per socket.
32 *
33 * Each PDU is one message. SCTP and IPC (a sequenced-packet socket) keep message
34 * boundaries and carry no prefix. TCP is a byte stream and prefixes each PDU
35 * with its length as four bytes in network order, in both directions. SCTP
36 * stamps payload protocol id 0x00E3A001 and sends indications on stream 1,
37 * everything else on stream 0.
38 *
39 * The RAN names each accepted connection with a token that is never reused
40 * (see E3Connector::last_peer_token) and can send to one peer or to all.
41 */
42class PosixE3Connector : public E3Connector {
43public:

45 * @brief Create a POSIX connector

50 * TCP and SCTP: "tcp://host:port" or "sctp://host:port" (a host in
