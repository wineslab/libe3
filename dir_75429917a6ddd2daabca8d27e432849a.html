Detailed Description

E3SM-L1KPM

E3SM-L1KPM is the E3 service model that gives a dApp the frequency domain IQ samples of each uplink slot of a RAN. The RAN does not send the samples in the E3 message. It writes them to a POSIX shared memory region on its host. Each E3 indication carries a small reference to the place in that region, plus the time, the frame number, the slot number and a few cell parameters. The dApp reads the samples from the region.

This service model is telemetry only. It has no control actions.

Item Value
E3 RAN function ID 2
Short name L1-KPM
RAN function revision (version in the RAN function data) 1

Everything of substance is in the numbered files. This page only says where.

Scope

The present document specifies the E3 service model "L1 KPM" (E3SM-L1KPM) for a RAN function that publishes the post-FFT uplink IQ samples of a cell to dApps on the same host as the RAN.

The present document defines the RAN function identity and the RAN function data, the information elements of the indication, the layout of the shared memory region that the indication refers to, the procedures, the encodings and the rules for erroneous data. The E3 messages that carry these elements are defined in the E3AP specification [1].

Terms, symbols and abbreviations

Terms

For the purposes of the present document, the terms and definitions given in the E3AP specification [1] and the following apply.

Indication: an E3 indication message whose ranFunctionIdentifier is 2. Its protocolData field holds one L1-KPM indication payload.

IQ row: the IQ samples of one uplink slot, stored as one row of the shared memory region.

Producer: the RAN software that writes IQ rows to the region and publishes them.

Consumer: the dApp software that reads IQ rows from the region.

Reference: the set of values (region name, buffer index, row index) that locates one IQ row.

Forwards and backwards compatibility

The ASN.1 types of this service model have no extension marker. A new field therefore changes the APER encoding, and a peer that does not know it cannot decode the message. The JSON and Protocol Buffers encodings ignore keys and fields that they do not know.

The region has a version number in its header. A consumer shall check it before it reads a row. The present document defines version 1.
